Point it at a zero table
and get a verdict.

Zero tables are load-bearing “trust me” files. Every numerical use of ζ depends on them, they arrive as opaque data, and there is no standard check step. This is the check step.

Each check catches a different failure

A table can be wrong in four independent ways. One test cannot catch all of them.

checkcatcheshow
structureswapped, duplicated, descending ordinates ordering and duplicate scan
residualsfabricated points |ζ(½+iγ)| at sampled ordinates, by two evaluators
independentsystematically wrong values ordinate comparison with mpmath's own zero finder
completenessmissing zeros count vs θ(T)/π+1, plus an argument-principle strip count

Completeness is the one that matters most and that residual checks cannot do: every listed ordinate can be correct while zeros are absent.

The one non-circular check

Most tests compare this code to itself. This one does not.

1.4e-11

Δγ vs mpmath

first 50 zeros against mpmath.zetazero, an independent implementation

1.2e-11

Δ Z(t)

at t = 1000 against mpmath.siegelz

1.9e-11

max |ζ|

mpmath's ζ evaluated at our claimed ordinates

Without mpmath installed, the independent check reports skipped — it does not silently pass.

Where this loses

The honest version of “how do you compare”, which is mostly unfavourably.

Arb / python-flint beats us on rigour

Arb gives rigorous enclosures and certified zero isolation with Turing's method for the count. Ours is float with a measured ~1e-12 agreement. Use Arb when you need proof-grade arithmetic.

mpmath beats us at evaluation

Arbitrary precision ζ, θ, and Z, widely reviewed. Ours exists to be dependency-free and to be the thing being cross-checked.

zeta-lab got to two-route verification first

Their zero layer pairs Arb isolation with an mpmath bracket check sharing no code with Arb, and documents the completeness caveat carefully. Ours adds an independent argument-principle count but at float grade.

LMFDB and Odlyzko own the tables

They publish the data (≈10¹¹ zeros, and the first 2,001,052). This audits a file; it does not replace the file.

The gap this fills is narrow: a CLI that takes an opaque table and returns pass/fail. The nearest existing work is a verification component inside a research codebase, not a tool aimed at someone else's file.
